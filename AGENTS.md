# AGENTS

Repository-specific guardrails for future changes:

- Treat JOSM coordinate spaces explicitly. Downloaded-area checks use `Bounds` with geographic coordinates. The visible-layer fallback intentionally uses the 0.2.0-style rendered layer: candidates are tracked in oversampled capture space, projected back through the slide-time capture bounds, and then carried as `EastNorth` only for preview/debug export.
- Managed mosaic origins and visualization corners are pixel boundaries, while decoded raster indexes are pixel-center samples. Managed sampling must map world pixels with `world-origin-0.5`, and managed candidate projection must add the same `0.5` back. Do not apply this correction to the visible rendered-layer transform without separate evidence.
- `MapView` capture scale is in projection units per view pixel, not ground metres. Measure slide-time ground scale through the active projection and keep it separate from raster oversampling, optional native tile resolution, and the legacy six-raster-pixel tracker normalization. Never label a projected scale or compatibility value as metres or native source pixels.
- Capture visible-layer tile zoom and native-resolution metadata while the virtual slide viewport is still active. Do not query tile zoom after restoring the user's viewport and then describe it as the sampled source resolution.
- Visible-layer alignment must render the selected segment extent at the required working resolution, using chunked virtual viewport captures when a single viewport would be too large. It must fail clearly when selected-segment profiles still fall outside the captured raster. Off-screen fallback profiles must not silently pull endpoints toward zero offset or lower confidence as if the heatmap itself were weak.
- The downloaded-area bypass is a heatmap-only drawing escape hatch and must remain opt-in. Do not make live alignment skip `Bounds` checks by default.
- Junction and endpoint movement must remain opt-in. When it is enabled in precise mode, do not simplify away selected/shared anchor nodes.
- Do not reintroduce uniform point redistribution after simplification in precise mode. Straight sections should be allowed to collapse more aggressively than curves.
- When precise mode drops interior nodes, clean up only nodes that are both untagged and unreferenced. Shared or tagged nodes must survive.
- Keep verbose/debug logging useful for remote diagnosis. For alignment bugs, log selected segment ids, exact redacted settings, sampled color schemes, sampled bands, chosen candidate offsets, candidate evidence/SNR, and applied node moves.
- Palette changes must come with regression coverage in `HeatmapFixtureArchiveTest` or `RidgeTrackerTest`, especially for `blue`, `gray`, and internal multi-color/dual-color detection, which are easy modes to mis-rank.
- Palette evidence is semantic, not always raw brightness. Keep `hot`/`blue`/`purple` single-ramp ordering separate from `bluered` and `gray`, where hue/saturation identify high-activity centers. Purple source tiles in current calibration data use a hue path near 260 degrees with bright lavender/near-white cores; do not revert purple detection to the older strict 285/315-degree-only mapping without fixture evidence.
- Broad saturated corridors must be centered on the high-intensity core, not on the whole low-threshold shoulder. Cross-section denoising should stay signal-gated and source-resolution-aware so it does not smear weak/no-signal areas into false evidence. The current profile filters run after color-to-intensity mapping and retain raw, B3 `[1,2,1]`, and B5 `[1,4,6,4,1]` centers; B5 drives denoised peak extraction, while B3 is the lighter stability comparison. Fine L0 localization uses two interleaved lateral phases, with B3/B5 kernel indexes dilated to retain their original physical support and with uncertainty bounded by the native source-pixel pitch. Coarse-scale centers are fallback position evidence weighted by `(1 - fine localization confidence)^2`; their persistence evidence remains independent. Peak and anchor scoring should prefer positions where raw/B3/B5 centers agree. Add/update sampler and tracker regression tests when changing plateau thresholds, filter powers/blends, anchor splitting, scale-position weighting, or longitudinal smoothing, and preserve real sustained switchbacks while suppressing one-profile shoulder aliasing, weak edge excursions, and sub-source-pixel alternating wiggles.
- `TrackerMode.CORRIDOR_AWARE` is the default from `0.20.0`. `TrackerMode.LEGACY_V02` remains an explicit compatibility fallback and must retain its existing peak extraction, ridge tracking, fallback, ranking, and safety behavior. Missing or invalid preferences use `TrackerMode.defaultMode()`; explicitly stored legacy preferences must round-trip unchanged.
- Legacy precise-shape candidates intentionally have no proposed-existing-node assignment map. Keep the legacy replacement path compatible with a null or empty map. Corridor-aware precise-shape candidates must carry a complete immutable assignment map and fail closed if it is absent.
- Keep corridor extraction, longitudinal strand association, parent/child grouping, and second-order centerline optimization isolated from `RidgeTracker`. Corridor-aware changes require full-profile, synthetic-raster, and real-fixture regressions; preserve complete native/B3/B5 diagnostics and never add a free post-optimization moving average.
- Corridor-aware subpixel interpolation starts only after pixels have been mapped to scalar intensity. Never interpolate across invalid raster support. Source-pixel size expresses localization uncertainty and cost normalization; it must not force candidate states onto an integer source-pixel grid.
- Corridor-aware metre thresholds must consume only the explicit monotonic cumulative ground distance carried by each profile sampling anchor. Raster coordinates remain image-sampling geometry; do not infer metres from raster oversampling or projected-pixel distance. Preserve the existing visible and managed profile locations when changing this contract.
- Longitudinal association may bridge at most 16 profiles and 20 metres. A lateral prediction residual above 1.5 source pixels requires sustained coherent evidence; temporary scale conflicts and coarse parent merges cannot authorize a strand switch.
- Tracker-approved gaps use one direction-independent convention: the higher-index/right observed boundary owns the bridge marker. Preserve that marker when forward and backward seed tracks merge; coverage must not accept either side indiscriminately.
- A corridor-aware candidate with incomplete longitudinal evidence is inspection-only. Do not let a short local strand outrank or become applicable over a complete native or aggregate corridor merely because its detector prior or local fit is high.
- Build endpoint approach tangents from the selected branch's robust corridor tube, never from the connected main-road tangent. Keep fixed endpoints exact and movable endpoints bounded and opt-in. Missing endpoint evidence is a diagnostic/ranking penalty, not by itself an applicability failure; independently proven foldbacks, unsupported terminal turns, and genuine pre-junction crossings remain blocking.
- Connected-way crossing checks must resolve movable shared nodes through the same immutable candidate-owned proposed-node assignments consumed by `ReplaceWaySegmentCommand`. Candidate and incident segments must meet at one proposed junction coordinate; missing, duplicated, non-finite, stale, or command-inconsistent assignments fail closed. Keep the sampling-resolution-aware junction tolerance. Detect short lateral excursions relative to the robust corridor tube, not from raw offset reversals that may represent supported curved geometry.
- Geometry-dependent safety checks must run on the stored final candidate preview after fixed-anchor reconstruction and permitted simplification, not only on the raw tracker ridge. Keep raw and final-preview geometry separately available for diagnosis.
- Topology safety must detect proper crossings, endpoint/vertex touches, and collinear overlaps. Ignore a connected-way contact only when every relevant intersection lies inside the source-resolution-aware shared-junction tolerance; a remote endpoint touch or overlap remains unsafe.
- The corridor-aware optimizer must remain one exact second-order pair-state dynamic program with bounded lateral states. Do not reintroduce global beam pruning, post-hoc smoothing, completed-geometry consensus, or a hidden refinement run. Candidate ranking and safety must use exported physical source-pixel/metre/degree quality metrics rather than objective-derived stability alone.
- The corridor tube keeps local 5 m and stability 12 m robust references plus a 32 m weak-signal reference. The extended reference may contribute only continuously under weak prominence and unsupported motion; sustained same-track direction or a supported apex must retain local geometry. Keep weak low-intensity sine/switchback amplitude and real sparse-corridor replay tests when changing these windows or the weak tube-prior bound.
- Sparse corridor parents supplement elementary children. Require all-pairs-compatible membership, at least 70% direct child-union support, physical tangent/separation/valley evidence, and bounded 16-profile/20-metre interpolation. Never count predicted-only points as direct coverage, hide child candidates, force a parent across persistent parallel modes, or let interpolation-only parent evidence authorize endpoint movement.
- Predicted sparse-parent contributors are geometric interpolation only: never include them in observed peak, noise, gradient, confidence, or motion-support statistics. For interpolation-only parent profiles, the 5/12/32-metre tube windows must remain physically bounded and must not expand to satisfy minimum profile counts.
- Exact-optimizer performance work may precompute profile-state and adjacent-state invariants and use deterministic indexed pair tables, but it must preserve the complete state space, arithmetic objective, offset sequence, tie order, transition count, and diagnostic cost rows. Every requested detector must still run and appear in detector-attempt diagnostics.
- For visible/source `bluered`, keep default candidate ordering biased toward `bluered-combined`, `bluered-corridor`, `bluered-cool`, and `bluered`. Generic brightness/corridor detectors such as `hot`, `hot-corridor`, `dual-corridor`, and `multi-combined` may be useful for exported calibration/manual preview, but should not outrank native bluered semantics by default because they can oscillate between corridor shoulders.
- Keep the visible-layer alignment path close to 0.2.0 unless the maintainer explicitly asks to reintroduce fixed-tile inference. No-signal profiles use zero-offset fallback peaks, seeds come from the first informative profiles, and long unsupported runs keep the last state just as 0.2.0 did. True no-signal candidates may be exported for diagnostics, but must not be applicable.
- Keep current-source alternative detectors and managed all-color aggregation as separate settings. Managed all-color aggregation must include an `all-colors-combined` candidate: fetch/cache base `hot`, `blue`, `bluered`, `purple`, and `gray` tiles, map each source through its native semantic intensity, aggregate scalar intensities, then run peak extraction and ridge tracking. The aggregate candidate must require all base color mosaics in the same sampling frame; never silently aggregate a subset. On the legacy visible rendered-layer fallback, only the selected rendered source exists, so alternative mappings can operate on that one raster but all-color aggregation is unavailable. Other combined classifiers must fuse named color-to-intensity mappings before peak extraction and ridge tracking. Do not add post-hoc geometry consensus, parallel-way scoring, separate fixed-tile validation, or internal refinement without explicit approval.
- Nearby-way corridor assignment is authorized only through the existing opt-in `parallelWayAwareness` setting in corridor-aware mode. Contextual OSM ways are read-only ranking evidence and must never be moved, retagged, simplified, or treated as proof of lane/carriageway semantics.
- Aggregate intensity visualization layers and debug PNGs must be generated from the same scalar all-color aggregate intensity path used by detection, rendered as white on transparent. The live visualization layer is created from settings acceptance, sits immediately above the managed Strava layer, uses the calibrated weighted power mean (`p=1.25`) to emphasize high-intensity source evidence without letting one source color dominate, and is diagnostic only. It must not feed back into alignment decisions.
- Direct intensity source modes bypass palette mapping and read rendered pixel luminance, max channel, or alpha as scalar intensity. Keep `Color mapping` as the default for Strava PNG heatmaps; do not claim or depend on a Strava raw numeric heat API unless it is documented and permitted.
- Experimental detector variants such as `hot-corridor`, `blue-corridor`, `bluered-cool`, `bluered-corridor`, `purple-corridor`, `dual-corridor`, `gray-magenta`, `gray-corridor`, `gray-strict`, and `purple-strict` are for visual rating and calibration. Every base detector mapping has a `-corridor` response applied after native palette-to-intensity conversion; the suffix must not select a different geometric tracker. Variants may influence default candidate ordering only through explicit calibrated ranking, and raw detector scores must remain exported so user-rated examples can be compared against the old candidates.
- Managed Strava settings create/refresh the visible TMS layer and, when all access values are configured, live sliding samples managed source tiles directly for fixed-resolution alignment. Without managed access values, the legacy visible-layer path remains the fallback; rendered colors then come from JOSM's normal layer rendering captured over the selected extent at the working resolution. The preview/debug output should record whether sampling used managed source tiles or the visible rendered layer, plus source tile zoom, capture bounds, chunk count, and effective sampling parameters.
- All plugin-direct managed tile requests must go through the plugin-owned tile coordinator. Keep transport reads, PNG decoding, cache I/O, retries, and blocking waits out of `AggregateIntensityLayer.paint`. Preserve bounded queue/memory/body limits, single-flight identity by generation/address/cache policy, negative retry eligibility, authentication/rate-limit circuits, stale-generation rejection before cache publication, and idempotent plugin/layer destruction.
- Diagnostic aggregate visibility must never expand alignment source acquisition. `AlignmentTileSourcePlan` requires the selected palette and adds the other four only for an explicitly requested all-color detector under color mapping. Patch-compatible 0.20.x aggregate detection remains strict: every required palette and zoom must be usable, and no subset becomes detector evidence or a normal complete diagnostic raster.
- Managed tile diagnostics may contain only numeric generation, purpose, activity, palette, z/x/y, safe status/content type, byte count, attempts, elapsed time, and bounded counters. Never include credential-derived fragments, Cookie headers, full signed URLs, response/error bodies, or arbitrary exception/server text. Configuration and parsed-cookie `toString()` methods must remain fully redacted.
- Stable fixed-scale sampling must not use broad max-dilation at the default z15 inference zoom; it can flatten the cross-section gradient and make off-center ways barely move. Keep any lower-zoom dilation small and covered by tests.
- The preview dialog is the place for ridge selection. Keep it modeless so users can pan/zoom and toggle layers while previewing. Keep candidate labels user-readable and avoid exposing raw internal scores as the primary UI.
- Candidate selection/rating after preview pan or zoom must use slide-time projected `EastNorth` candidate geometry. Never reproject stored raster/screen candidate points through the current `MapView` unless no slide-time geometry exists.
- Modeless preview apply must be guarded against stale source geometry. Revalidate the way node sequence, selected segment identities, dataset membership, and source coordinates before candidate switching and before apply.
- Repeated-node selections are unsafe unless occurrence identity is explicitly modeled. Reject selected segments where a segment node appears more than once in the same way, including outside the selected range.
- Last-slide debug export should prioritize the most recent slide attempt and include the rendered heatmap capture, redacted settings, sampled colors, original/preview/candidate geometry, candidate evidence, source tile zoom, viewport bounds, source meters per pixel, effective view/raster meters per pixel, configured/effective cross-section width and step, estimated visible tile ranges, per-detector cross-section peak data, candidate/profile/palette CSV calibration exports, sparse bundle and bundle-point provenance, and per-slide logs. Never export cookies, signed headers, or full signed URLs.
- Post-Apply debug export must serialize the original segment from the immutable pre-command `AlignmentResult.sourcePolyline`, not mutable JOSM node coordinates. Format-5 bundles keep immutable original, proposed preview, raw candidates, final candidate previews, and actual applied geometry distinct.
- Verbose logs should also include the full redacted alignment settings JSON, including inference mode (`STABLE_FIXED_SCALE` vs `RAW_HIGH_RESOLUTION`), inference/validation zooms, intensity source, and cache-buster state, so console-only reports can still identify the active sampling mode.
- Cross-section peak diagnostics should preserve gradient strength/balance and candidate evidence should preserve mean gradient strength plus longitudinal stability; these metrics help distinguish true ridges from noisy intensity-only maxima.
- Corridor-aware Gaussian scale space must be built after scalar intensity mapping from imagery already acquired for the slide. Use separable B5 filtering with fixed-phase 2x decimation, preserve invalid support, and do not download lower zooms to synthesize or validate levels.
- Cross-scale evidence may influence one fine-coordinate optimizer but must never average or vote on completed geometries. When fine parallel children merge into a coarse parent, the parent may add persistence but must not supply a midpoint or collapse child identity.
- Keep detector attempts and rejected candidate geometry through preview and debug export. Rejected/no-signal candidates may be inspected and rated but must never enable Apply. Native/complete-aggregate source tiers must be evaluated before cross-palette alternatives.
- Keep `scripts/analyze-debug-bundles.py` compatible with exported bundles when changing candidate metrics, ratings, or CSV diagnostics.
- Format-6 diagnostics use unit-explicit physical sampling fields, canonical bridge ownership, per-detector phase/operation records, and dedicated checksummed CSV artifacts instead of duplicating complete profile arrays in `diagnostics.json`. Format 7 adds candidate-owned proposed-node positions and complete original/proposed junction-segment evidence. Keep formats 1-6 readable and mark format-5 visible-layer metre fields untrusted.
- Candidate ratings and negative feature tags from the opt-in preview rating mode are calibration data. Preserve them in `candidate-ratings.json`, `status.json`, and verbose log lines when changing diagnostics export behavior.
- Rough full-way 2-5 node selections may be recognized in UI/debug metadata, but the current visible-layer path keeps the configured alignment mode to preserve predictable sliding behavior.
- Rough full-way 2-5 node selections must not silently widen managed source-tile search beyond the configured search half-width. If a mapper needs a wider rough-sketch search, it must be explicit in settings; automatic widening can jump to unrelated parallel traces.
- Candidates with abrupt lateral jumps or acceleration are structurally unsafe even when heatmap SNR is high. Keep candidate safety warnings exported and block preview/apply for those candidates rather than relying only on signal strength.
- Precise-shape simplification must run after fixed anchors are restored and per fixed-anchor interval. Do not simplify the whole traced centerline before fixed-anchor interval reconstruction.
- Precise-shape undo/redo must replay stored target coordinates for reused existing nodes on every command execute/redo, not only during first replacement-node construction.
- Reusable mutable nodes in precise mode must be matched monotonically by original and preview path-length fraction. Never consume node identities in preview iteration order; fixed, tagged, shared, referenced, and endpoint anchors retain their existing protections.
- Keep the fixture regression acceptance envelope and `acceptable-limits.osm` generation tied to the same configured metric radius. Visual limit changes must be reflected in the regression oracle too.
- `acceptable-limits.osm` is a regression/visualization artifact only. Do not reuse its envelope logic inside the live alignment workflow.
- Release versioning must match the scope of change. Stay on `0.x.x` until the maintainer declares the plugin suitable for broader use. After `1.0.0`, use `1.x.x` for major functionality or architecture changes, `1.1.x`-style minor releases for smaller features and improvements, and `1.1.1`-style patch releases only for bug fixes. Release naming follows the JOSM AudioWptMarker convention: tag/release name `v<version>`, primary jar asset `wayheatmaptracer.jar`, and semantic version in the jar manifest `Plugin-Version`.
- Geometry cleanup settings are future-candidate-only and disabled by default. Accepting the cleanup dialog must not mutate OSM data; retain the raw final-preview candidate whenever cleanup is skipped, rejected, or produces no safe alternative.
- Cleanup must never receive a ranking bonus merely for reducing point count. A cleaned sibling is applicable only after the final-preview evidence, protected-anchor rules, fresh assignments, and all geometry/topology safety checks pass independently.
- Final-preview cleanup requires a monotonic one-to-one mapping from every movable preview occurrence to slide-time cleanup evidence. An inserted fixed/shared/tagged/junction anchor may replace one adjacent raw-profile point only in the cleanup working geometry; keep it exact, mark its borrowed row unsupported/boundary-only, and never let it contribute direct signal, fit, motion, or turn authorization. Missing, duplicated, interpolated-only, off-raster, no-signal, or non-monotonic movable mappings fail closed.
- Cleanup thresholds must use the factual slide-time ground metres per raster pixel carried by the cleanup sampling frame. Projection units, viewport pixels, oversampling factors, and legacy compatibility units must never be substituted for that physical scale.
- Cleaned precise candidates must rebuild an immutable candidate-owned proposed-node assignment map after smoothing/reduction. No cleanup service may create, move, simplify, retag, or delete dataset primitives outside the existing apply command, whose stored assignments must continue to support exact undo/redo.
- Format-9 cleanup diagnostics are additive: preserve formats 1-8, emit explicit raw-parent/cleaned-sibling and anchor-occurrence fields, checksum dedicated cleanup CSV artifacts, and make analyzers report missing cleanup artifacts as unavailable rather than zero.
- Format-10 optimizer diagnostics add robust residual amplitude/trend authorization and a separate absolute short-wave turn cost. Keep attribution (`unsupportedRippleFactor`) separate from authorization (`trendAuthorization`), and keep the absolute term separate from tube-relative acceleration. Missing format-10 fields in formats 1-9 are unavailable, never measured zero.
- Cleanup-enabled ripple attribution must use contiguous direct evidence, a minimum physical span, factual two-sided direct coverage, a confidence/uncertainty-weighted robust affine trend, and source-pixel-normalized residual amplitude. Tiny residuals below onset, scale conflicts, sparse interpolation, boundary-censored windows, and insufficient spans must not authorize intervention. One endpoint-ownership gate applies to every cleanup-only optimizer contribution: tube pull, continuity amplification, relative-curvature amplification, and absolute short-wave turn cost. The absolute turn term stays inside the one exact pair-state DP and every cleanup-only term must be exactly zero when cleanup or ripple strength is disabled.
- Geometry cleanup schema 2 stores one effective choice. Named Conservative/Balanced/Strong choices enable constrained cleanup; migrated or malformed disabled settings remain Off. Every named preset uses the same fixed 6/10/20 m local-shape analysis bank, with preset strength applied only after classification.
- Local cleanup defects are immutable interval boundaries, not permission to fabricate evidence or a reason to disable unrelated valid intervals. Smoothing requires positive wrinkle intervention and independently backtracks intervals; simplification retains protected, frozen, high-ambiguity, and bend-supported profiles exactly. A valid mixed result is `PARTIALLY_CLEANED` and still has at most one cleaned sibling.
- Format-12 diagnostics add checksummed coordinate-free local-shape evidence and distinguish highest-ranked applicable base, initial preview, and current selection. Keep older formats readable and never serialize private calibration coordinates or absolute archive paths.
- Cleanup may condition ridge optimization only for Corridor Aware + Precise Shape. In every other alignment/tracker mode, detection and final-preview construction must receive an effective disabled cleanup config while sibling expansion retains the requested config only for an explicit ineligible report. A protected inserted anchor may borrow only one immediately adjacent raw profile; nonadjacent chainage/transform borrowing fails closed.
