# v0.20.1 Tile Reliability Implementation Record

## Scope

Implemented the approved patch-safe tile reliability foundation from the exact
`v0.20.0` baseline. Detector mathematics, sampling geometry, candidate ranking,
topology checks, cleanup, preview geometry, and OSM edit commands were not
changed. Explicitly requested all-color detection remains strict and requires
all five palettes at all required zooms.

## Decisions

- Kept JOSM's managed visible TMS layer and centralized only plugin-direct tile
  requests.
- Used one encapsulated `HttpURLConnection` transport because credential-header
  suppression in JOSM DEBUG logging was not proven at baseline 19555.
- Used a three-worker bounded priority coordinator with single-flight,
  generation-aware positive/negative cache state, one required transient retry,
  authentication and rate-limit circuits, and safe consumer cancellation.
- Rendered live aggregate tiles only after complete 5/5 source success and moved
  even immediate memory-cache aggregation off Swing paint through bounded worker
  dispatch.
- Kept CP9 behavior changes deferred. Incomplete explicitly requested detector
  aggregates still fail the slide rather than continuing selected-source tracing.

## Privacy And Recovery

Credential containers, managed configuration, and parsed cookie values have
fully redacted string forms. Transport errors use controlled status/reason text;
diagnostics contain no Cookie header, signed URL, response/error body, arbitrary
server message, or credential-derived fingerprint. Old cache layout reads remain
compatible, corrupt or oversized entries are removed individually, and atomic
validated writes prevent partial positive entries.

Rollback is the `v0.20.0` commit `46b2fa1`. No push, tag, release, private archive
access, or external network test was authorized or performed by this plan.
