# v0.17.1 Proposed-Junction Topology Safety

**Status:** Implemented and authorized for publication as `v0.17.1` on 2026-08-04. Runtime validation remains the gate before starting the separate `v0.18.0` plan.

**Goal:** Release a narrow `v0.17.1` correction that evaluates movable shared junctions and every incident way in one consistent proposed geometry, without changing heatmap detection, corridor optimization, candidate ranking, or fixed-junction behavior.

**Why planning is required:** The correction affects the safety gate that decides whether modeless preview geometry may mutate shared OSM nodes. The current `v0.17.0` code compares a candidate at its proposed junction position with connected segments that still terminate at the old junction position. That can reject valid candidates, while an incorrect repair could instead admit a real pre-junction crossing or make safety disagree with the undoable command. The release must establish one explicit proposed-node contract shared by preview, apply-time revalidation, diagnostics, and command execution.

**Acceptance:** `v0.17.1` is based directly on `v0.17.0`. A candidate carries an immutable mapping from every selected existing node whose position matters to topology to its exact proposed `EastNorth` coordinate. Connected-way safety resolves both endpoints of every adjacent segment through that mapping and permits only the shared touch at the proposed junction within the existing ground-metre tolerance. Fixed nodes retain their source coordinates. Preview safety, modeless apply recheck, and `ReplaceWaySegmentCommand` use the same proposed coordinates. Real crossings, self-intersections, stale selections, newly added connected ways, and changed adjacent geometry remain blocked. Execute, undo, and redo move and restore shared nodes atomically without changing unrelated primitives. The supplied `last-slide-debug-1785794101840.zip` no longer reports the demonstrated stale-position crossings for its nine complete candidates when replayed locally, while incomplete and independently unsafe candidates remain inspection-only. No detector output, palette mapping, profile sampling, optimizer offset, or legacy behavior changes. Full tests, Javadoc, debug redaction, packaging, and manifest checks pass before an explicitly authorized publication.

## Confirmed Evidence

- `last-slide-debug-1785794101840.zip` was generated by plugin `0.17.0` in `CORRIDOR_AWARE`, `PRECISE_SHAPE`, stable z15 mode with `adjustJunctionNodes=true`.
- Nine candidates have complete longitudinal corridor coverage. Every one is inspection-only because `connected-way-crossing` is evaluated against junction node `4894426654` at its source coordinate.
- Re-evaluating those candidate and incident-segment pairs after replacing the shared endpoint with each candidate's proposed junction coordinate removes the nine demonstrated findings. This does not establish that every other candidate is safe; all other warnings must still be evaluated independently.
- `AlignmentService.connectedWayCrossings` currently obtains `junctionPoint`, `connectedStart`, and `connectedEnd` directly from mutable source nodes after selecting candidate final-preview geometry. It does not carry the candidate's proposed shared-node coordinate into the connected segment.
- `ReplaceWaySegmentCommand` separately derives movable endpoint, tagged-node, and shared-node targets as soft anchors. Safety and command execution therefore have duplicate, potentially divergent projection logic.

## Fixed Design Decisions

- Scope the patch to final-preview topology state, command consistency, diagnostics, and tests. Do not alter `CorridorExtractor`, `CorridorTracker`, `CorridorGrouping`, `CorridorTubeBuilder`, `CorridorCenterlineOptimizer`, palette mappings, ranking weights, or safety thresholds.
- Do not infer proposed node identity by choosing the nearest preview point. Build an explicit node-identity mapping while final preview geometry is constructed.
- Keep junction/end movement opt-in and preserve every existing hard displacement bound and original-position prior.
- Evaluate the topology that the command would create: a moved shared node changes the endpoint of every referring way segment because those ways share the same node object. Non-junction endpoints remain at their current coordinates.
- Preserve the current rule that only segments immediately adjacent to a shared junction participate. Remote segments of a connected way remain outside this check.
- Keep the existing source-resolution-aware tolerance in ground metres. Do not compare projection-unit distances as metres and do not enlarge the tolerance to hide stale-coordinate findings.
- Fail closed when a required proposed node coordinate is missing, duplicated, non-finite, outside its displacement bound, or inconsistent with the final preview or command plan.
- Keep supplied ZIPs, OSM ground truth, console logs, and extracted artifacts untracked.

## Stop Conditions

- Stop if a candidate can pass preview safety but produce different existing-node coordinates when its command is constructed.
- Stop if a fixed, tagged, shared, endpoint, or referenced node is replaced, duplicated, simplified away, or moved outside its configured bound.
- Stop if a true pre-junction crossing, final-preview self-intersection, or stale modeless source state becomes applicable.
- Stop if any detector geometry, palette mapping, optimizer checksum, legacy ordering, source sampling, tile request, or unrelated OSM primitive changes.
- Stop publication if local `main`, `origin/main`, version metadata, tag target, jar manifest, or GitHub release state disagree. Never delete or rewrite remote state to resolve a collision.
