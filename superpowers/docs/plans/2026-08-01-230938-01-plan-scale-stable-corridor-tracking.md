# Scale-Stable Corridor Tracking And Transparent Detector Results

**Status:** Implemented and verified for v0.15.1. Release publication is tracked by the `v0.15.1` tag and GitHub release.

**Goal:** Make the experimental corridor-aware tracker produce visually smooth, scale-invariant centerlines from broad through sparse heatmap signals, rank mappings according to the actual source palette, and show what happened to every requested detector in preview and debug output.
**Why planning is required:** The fix crosses raster coordinate systems, scalar palette conversion, Gaussian scale space, corridor identity, dynamic-programming units, candidate ranking, preview safety, diagnostics compatibility, and release behavior. The currently working legacy tracker and OSM edit safeguards must remain isolated while several dependent contracts change in the experimental path.
**Acceptance:** `TrackerMode.LEGACY_V02` remains the default and its existing tests and fixture output remain unchanged. `CORRIDOR_AWARE` corrects its source-pixel/profile-spacing normalization, uses an in-memory L0/L1/L2 scalar Gaussian pyramid derived only from imagery already acquired for the slide, and never fetches a lower-zoom tile merely to validate stability. On straight or gently curving broad corridors, randomized hot-pixel aliasing must produce no visible alternating left/right sawteeth and a high-frequency cross-track RMS no greater than `0.25` source pixel with p95 residual no greater than `0.50` source pixel at tested source-pixel scales `1`, `6`, and `24`; the same physical fixture must remain within `0.25` source pixel between scale configurations. Sustained sine curves and switchbacks retain at least 90% of their intended amplitude, weak narrow persistent strands remain traceable when they disappear at coarse levels, and coarse parent merging never pulls a fine child track into a neighboring parallel trail. With a configured `hot` source, every requested run records a `hot` detector attempt; an applicable native hot-family candidate ranks ahead of cross-palette mappings, while rejected or empty hot attempts remain visible with a reason. Unsafe/no-signal candidates can be inspected but never applied. Debug exports retain all attempts, candidates, scale evidence, objective terms, and ranking components without credentials. The full Java/Python/fixture suite passes before publishing bugfix release `v0.15.1` with asset `wayheatmaptracer.jar`.

### Outcome 2: Correct the corridor optimizer's dimensional normalization

- Work: Refactor only `CorridorCenterlineOptimizer`; do not alter `RidgeTracker`. Express each allowed state as its actual sampled-raster point `anchor + normal * offset`. For adjacent profiles define longitudinal spacing in source pixels as `spacingPx / sourcePixelSizePx` and lateral displacement in source pixels as `deltaOffsetPx / sourcePixelSizePx`; their ratio simplifies to `deltaOffsetPx / spacingPx`, so do not divide the resulting slope by `sourcePixelSizePx` again. Calculate the second-order term from successive geometric segment directions/heading changes and average longitudinal spacing, so rotating normals and curved source geometry are handled in raster space rather than as unrelated scalar offsets. Keep state costs invariant when all raster coordinates and `sourcePixelSizePx` are multiplied by the same factor. Update `CostRow` so its reported continuity, acceleration, and weighted total are exactly the values used by dynamic programming rather than differently normalized post-hoc approximations. Temporarily keep turn relaxation conservative until cross-scale support is available in Outcome 5.
- Risks/open questions: A pure offset second derivative is not equivalent to geometric curvature when profile normals rotate. Tests must compare actual candidate points as well as offsets.
- Verify: `sh gradlew test --tests '*CorridorCenterlineOptimizerTest' --tests '*CorridorScaleInvarianceTest' --tests '*CorridorRasterIntegrationTest'`

### Outcome 3: Introduce a bounded scalar-intensity scale-space abstraction

- Work: Add `ScalarIntensityField`, `IntensityScaleLevel`, and `GaussianIntensityPyramid` (or equivalently named single-purpose types) under `service/`. L0 is produced after RGB-to-intensity conversion: current-source alternatives each map the current raster independently; direct intensity modes first read their selected scalar channel; `all-colors-combined` first maps every required source with its native semantics and performs the existing weighted power mean, then builds one pyramid from that aggregate L0. Never blur RGB before semantic mapping. Build L1 with a separable two-dimensional binomial/Gaussian kernel `[1,4,6,4,1]/16` in each axis followed by fixed-phase 2x decimation; build L2 by repeating L1, giving 1x/2x/4x analysis pitches and deterministic affine transforms back to L0/base-raster coordinates. Preserve a validity mask and require a two-pixel source-level halo; do not zero-pad missing/out-of-raster data into false edges. Managed mosaics use their native source-pixel grid. For the visible-rendered fallback, retain the rendered L0 for final localization and construct the source-grid pyramid using the slide-time `sourcePixelSizeRasterPx` estimate and an explicit base-to-level transform. Record whether the source-pixel estimate came from a reported tile zoom or the existing fallback.
- Risks/open questions: Full captures and many mappings can be large. Process one detector mapping at a time, use bounded tiles/chunks with convolution halos, release level buffers after profiles/diagnostics are extracted, and keep peak additional working memory below 128 MiB. If a level cannot be built, mark that level unavailable for the affected profiles; do not silently substitute zeroes or fetch another zoom.
- Verify: `sh gradlew test --tests '*GaussianIntensityPyramidTest' --tests '*RenderedHeatmapSamplerProfileTest' --tests '*TileHeatmapSamplerTest'`

### Outcome 5: Turn cross-scale persistence into uncertainty-gated evidence, not geometry consensus

- Work: Extend `CorridorBand`, `CorridorTrack`, and their evidence models with `scalePersistence`, coarse-center estimate, coarse uncertainty, participating levels, and an explicit scale-conflict/parent-merge state. Use initial persistence weights L0=`0.50`, L1=`0.35`, and L2=`0.15`, renormalized over available compatible levels; these weights describe evidence only. A fine child receives persistence from a coarse parent envelope but not the parent's midpoint. A fine narrow strand that is longitudinally persistent at L0 remains valid when absent at L1/L2; absence lowers scale confidence but is not no-signal proof. A one-profile excursion that disappears at L1 and lacks longitudinal support is penalized. Do not run three independent trackers and average or vote on finished geometries. Feed one corridor identity and its cross-scale evidence into one fine-coordinate optimizer, preserving the repository prohibition on post-hoc geometry consensus.
- Risks/open questions: Coarse merging is expected near parallel roads and tight switchbacks. Mark it as ambiguity and suppress the coarse-center prior locally instead of forcing a parent interpretation.

### Outcome 6: Make broad plateaus smooth while preserving detailed supported turns

- Work: Revise `CorridorCenterlineOptimizer.dataCost` so insignificant intensity variations inside a high core do not pull the path toward alternating hottest pixels. Calculate a per-profile normalized intensity deadband from cross-scale disagreement: start with `epsilon = clamp(0.02 + 0.5 * mean(|raw-B3|, |B3-B5|), 0.02, 0.10)` and assign equal peak-fit cost to values within `epsilon` of the selected-band maximum. Continue to penalize leaving the robust core and sharply penalize leaving the shoulder. Within the deadband, prefer the nested-boundary center and the compatible L1/L2 center according to localization uncertainty and scale persistence. Set coarse-prior weight continuously: strongest for a broad, poorly localized fine plateau with compatible persistent coarse evidence; weak for a narrow, well-localized strand; zero for a scale conflict or fine-child/coarse-parent merge. Replace the current three-profile `sustainedCenterMotion` relaxation with a physical support window of approximately 10 metres, clamped to 5-9 profiles. Relax geometric curvature cost only when at least 70% of that window supports coherent motion, raw/B3/B5 centers agree, scale evidence does not conflict, and displacement exceeds center uncertainty. Retain at least 65% of the normal acceleration weight at confirmed turns and never apply a post-optimization moving average.
- Risks/open questions: Excessive coarse-prior weight can narrow sine curves or round switchback apices. Keep all parameters package-private and require amplitude/curvature regression evidence before tuning them.
- Verify: `sh gradlew test --tests '*CorridorCenterlineOptimizerTest' --tests '*CorridorScaleInvarianceTest' --tests '*CorridorRasterIntegrationTest' --tests '*MultiScaleCorridorTrackingTest'`
