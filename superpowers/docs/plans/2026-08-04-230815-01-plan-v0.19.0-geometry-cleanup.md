# v0.19.0 Evidence-Gated Geometry Cleanup

**Status:** Complete; all 11 checkpoints passed and v0.19.0 was published.

**Goal:** Release `v0.19.0` with separately configurable, evidence-gated ripple suppression and an optional cleaned preview that applies heatmap-constrained Laplacian smoothing followed by heatmap-constrained Douglas-Peucker point reduction, without changing legacy tracking, silently replacing raw candidates, or weakening OSM topology safety.

**Why planning is required:** The feature changes the corridor-aware objective, persistent settings, candidate geometry, preview selection, node reuse, diagnostics, and the final geometry that an undoable JOSM command may apply. Incorrect smoothing could erase real switchbacks, leave a strong heatmap center, merge parallel corridors, move shared nodes, create crossings, or make preview and apply disagree. The work therefore needs resumable checkpoints with focused regression gates before any publication.

**Acceptance:** `Geometry Cleanup Settings` is available from both `More tools` and the main WayHeatmapTracer settings, but only configures future slides and never edits the currently selected way. Cleanup modes are `None`, `Reduce points only`, and `Constrained smoothing + reduce points`; smoothing-only output is not a normal user mode. Conservative, Balanced, and Strong presets use unsupported-ripple scales of 6, 10, and 20 metres respectively. Cleanup is disabled by default. `LEGACY_V02` tracking remains the default and retains its current output under unchanged settings. The initial new smoothing scope is `CORRIDOR_AWARE` plus `PRECISE_SHAPE`; existing reduce-points-only behavior remains migration-compatible. Every eligible detector keeps its raw candidate and may add at most one clearly related cleaned candidate. The cleaned path is processed per protected-anchor interval, moves points only laterally, remains inside the selected corridor, retains calibrated raw/B3/B5 fit, preserves supported bends and at least 90% switchback/sine amplitude, and then reduces points without bypassing supported geometry. Fixed, tagged, shared, endpoint, and junction nodes are never removed; candidate-owned movable endpoint/junction targets are frozen during cleanup. All final-preview safety and stale-source checks are rerun. Full Java/Python tests, fixture archives, Javadoc, diagnostics compatibility, performance checks, packaging, manifest verification, independent review, and explicit publication authorization are required before release.

## Fixed Design Decisions

- Create one `GeometryCleanupSettingsDialog`. Open it from `More tools -> Geometry Cleanup Settings...` and from a `Geometry cleanup...` button in `HeatmapSettingsDialog`.
- The direct menu action is configuration-only. It requires no selection, creates no JOSM command, mutates no OSM primitive, and does not clean an already selected way.
- Capture cleanup settings once at slide start. Changing settings while a modeless preview is open does not alter that preview; the mapper must run Slide again.
- Store cleanup settings in a separate immutable `GeometryCleanupConfig`, not as more heatmap-source fields. Compose it with `ManagedHeatmapConfig` only in the immutable slide-time request/result contract.
- Provide modes `NONE`, `REDUCE_POINTS_ONLY`, and `CONSTRAINED_SMOOTH_AND_REDUCE`. There is no normal `SMOOTH_ONLY` mode.
- Preset ripple scales are exactly Conservative `6 m`, Balanced `10 m`, and Strong `20 m`. Other strength, pass, tolerance, and fit-retention values remain named calibration parameters until fixtures justify final defaults.
- Keep one exact corridor optimizer execution per track. Ripple configuration adjusts its existing evidence-gated continuity/acceleration family; it does not trigger a hidden second optimizer, refinement loop, or geometry consensus.
- The raw candidate means the optimizer output before geometry cleanup. It remains selectable and keeps its stable detector identity. A successful cleaned alternative is related by explicit parent id and is labeled `cleaned`; a failed cleanup records a diagnostic attempt and leaves the raw candidate usable.
- Generate no more than one cleaned alternative for each complete corridor-aware candidate. Incomplete/no-signal candidates retain raw diagnostic geometry and record why cleanup was skipped.
- Laplacian cleanup operates on the dense slide-time preview after fixed anchors are reconstructed and per fixed-anchor interval. It uses cumulative ground metres, not point counts, view pixels, current zoom, or projection-unit assumptions.
- Laplacian displacement is projected onto the local normal. It must not redistribute points longitudinally, densify geometry, or import the referenced plugin's optional density-increase behavior.
- A smoothing move is accepted only while it stays in the selected candidate's corridor and retains the configured combined raw/B3/B5 fit. Weak sparse bundle evidence may constrain smoothing through its direct-union tube; predicted-only/no-signal evidence cannot authorize movement.
- Point reduction always follows Laplacian smoothing in `CONSTRAINED_SMOOTH_AND_REDUCE`. It uses Douglas-Peucker geometry error plus corridor, intensity, supported-turn, and topology constraints.
- Treat proposed movable endpoints and junctions as protected cleanup anchors at the exact candidate-owned coordinates already validated by preview topology. Cleanup may simplify their adjacent interval but may not choose another target or remove the shared node.
- Keep current candidate final-preview reconstruction, immutable proposed-node assignments, modeless stale-state revalidation, command execution, undo/redo, and orphan cleanup contracts.
- Do not copy source from the GPL-3.0 LaplacianSmooth plugin into this repository without an explicit compatible licensing decision. Implement the standard line-smoothing mathematics independently and document its provenance and parameters.
- This is a `0.19.0` feature. Release corrections after publication use `0.19.x` patch versions.

## Execution Order And Stop Conditions

1. Execute one checkpoint at a time. Do not start its production edits until its required red test or baseline evidence exists.
2. Before editing, set only the current ledger row to `in_progress`. At completion, inspect `git status`, preserve unrelated changes, run the named focused verification, review the diff, update that row to `complete`, and leave a short handoff containing changed files, commands, results, remaining red tests, and the next checkpoint number.

4. Stop if cleanup-disabled raw candidate ids, offsets, ranking, final preview, legacy fixture output, palette mapping, source sampling, or exact-optimizer tie/state behavior changes.
5. Stop if any metre threshold derives from raster/view pixels, profile count, current viewport, or uncorrected projection units.

7. Stop if smoothing or reduction uses predicted-only/no-signal evidence to invent geometry, crosses a corridor valley into a parallel trace, or silently fills an unbounded gap.
8. Stop if a fixed/shared/tagged node or candidate-owned endpoint/junction target is removed, duplicated, independently retargeted, or moved outside existing bounds.
9. Stop if cleaned preview safety and the command disagree, Undo/Redo changes unrelated primitives, or simplification leaves orphaned tagged/referenced nodes.
10. Stop if a failed cleanup hides the raw candidate, suppresses a safety warning, or becomes applicable through a point-count/ranking bonus.
11. Stop if implementation requires copied GPL-3.0 source without a compatible repository licensing decision.
12. Stop publication if tests, Javadoc, analyzer compatibility, redaction, runtime/memory evidence, version, manifest, tag, release asset, or remote commit checks disagree.
