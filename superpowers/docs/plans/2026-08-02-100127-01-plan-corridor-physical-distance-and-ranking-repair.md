# Corridor Physical Distance, Coverage, Ranking, and Debug Repair

**Status:** Implemented and verified for release `v0.16.2`.

**Corrective follow-up:** The visible rendered-layer pixel-to-ground naming and normalization issue discovered after this release is addressed by [`2026-08-02-221142-01-plan-visible-rendered-pixel-ground-scale-repair.md`](2026-08-02-221142-01-plan-visible-rendered-pixel-ground-scale-repair.md). This note does not alter the historical `v0.16.2` status or findings.

**Target release:** `v0.16.2` bugfix release. Do not change the legacy tracker or palette calibration in this work.

**Goal:** Repair the `v0.16.x` corridor-aware regression by carrying real cumulative ground distance independently of raster coordinates, requiring longitudinally complete evidence before Apply, ranking measurable candidate quality ahead of detector priors within a source tier, checking junction crossings on final preview geometry, and exporting immutable before/after diagnostics.

**Why planning is required:** One coordinate-space defect currently affects strand gap bridging, robust-tube windows and tangent units, endpoint approach discovery, physical quality metrics, applicability, ranking, and remote diagnostics. The supplied `problems-4.zip` also exposed a second contract defect: the post-Apply debug export reconstructs the alleged original geometry from mutable JOSM nodes. Fixing only a threshold or ranking weight would leave the underlying evidence invalid and could make unsafe candidates easier to apply.

**Acceptance:** `TrackerMode.LEGACY_V02` remains the default and retains its current sampling, tracking, fallback, ranking, safety, preview, and apply behavior. In corridor-aware mode, raster coordinates are used only for image sampling and raster geometry; every metre threshold uses an explicit monotonic cumulative-ground-distance value. A transient mismatch may bridge only when both the 16-profile and 20-metre limits pass, an endpoint guide can find reliable evidence 8-15 metres inward at normal z15 sampling, and exported physical distances agree with source geometry rather than raster scale. Candidates covering only a local island cannot be applied or outrank a longitudinally complete candidate. Within the same native/aggregate source tier, the measurable full-corridor candidate wins before detector priors are considered. Connected-way crossing warnings describe the final fixed-anchor preview and include enough context to reproduce the decision. Format-5 debug bundles preserve immutable original, proposed, and actual applied geometry; record plugin version, real profile spacing, ranking components, coverage, and exact safety evidence; and contain no credentials. All focused tests, the full Gradle suite, Javadoc, Python checks, packaging checks, and analyzer compatibility checks pass before release.

## Confirmed Baseline

- In `problems-4.zip`, managed z15 sampling reports `23.957135` raster pixels per source pixel and `1.553221 m/source-pixel`. Consecutive rows in `corridor-tube.csv` are nevertheless separated by about `40.11298` alleged metres. The actual ground spacing is approximately `40.11298 / 23.957135 * 1.553221 = 2.60 m`.
- `RenderedHeatmapSampler` currently creates `CrossSectionProfile.anchor` from the raster point. `CorridorTracker`, `CorridorTubeBuilder`, and `EndpointApproachBuilder` then consume that field as metres. The new physical-distance checks were introduced in `v0.16.0`; `v0.15.1` used only a profile-count gap bound.
- First-way rank 1, `all-colors-combined/strand-2`, observes only profiles `2..99` of 369, leaves a 269-profile run unsupported, reports optimizer cost `76.931772`, tube residual p95 `25.495972` source pixels, and true persistence `0.037504`, yet remains applicable.
- First-way `hot-corridor/strand-8` observes profiles `2..368` of 369, has optimizer cost `0.119851`, tube residual p95 `0.442995`, persistence `0.584338`, and calibrated score `1.441292`, but is inspection-only because of one connected-way crossing warning.
- Second-way rank 1, `hot-corridor/strand-4`, observes profiles `49..83` of 152, has optimizer cost `61.349068`, tube residual p95 `23.680591`, and persistence `0.039861`. The visually better `hot/strand-8` observes `67..147`, has optimizer cost `0.374505`, tube residual p95 `1.497252`, and persistence `0.362762`, but is ranked second.
- Every examined detector has at least one exported elementary band at every profile, so these short tracks are association termination, not absence of all profile evidence. Once a track terminates, the optimizer allows exactly one interpolated or extrapolated offset on each untracked profile, producing a smooth but weakly supported line.
- `v0.16.1` correctly stopped treating missing endpoint-guide evidence alone as a blocking warning, but all endpoint guides in the supplied runs are falsely unsupported because the immediately adjacent raster anchor already appears farther than the 15-metre search limit.
- The exact `hot-corridor/strand-8` crossing decision cannot be reproduced from format-4 bundles because connected way/node ids, adjacent segment geometry, intersection coordinate, candidate segment, measured distance, and tolerance are absent.
- On status `applied`, `LastSlideDebugBundle` is rebuilt after the JOSM command and serializes `selection.segmentNodes()` for `original-segment.osm`. Those are mutable or removed node objects, not the immutable pre-slide `AlignmentResult.sourcePolyline`; therefore format-4 before/after geometry and analyzer length comparisons are not trustworthy after Apply.

## Fixed Design Decisions

- Preserve the current profile locations and detector/palette behavior in this bugfix. Do not change color-to-intensity mappings, Gaussian kernels, optimizer weights, search width, source-tile zoom, or completed-line smoothing while repairing units and coverage.
- Add an explicit profile sampling-anchor contract containing: the source `EastNorth` map coordinate, the sampled-raster coordinate, and monotonic cumulative ground distance in metres. Never infer metres downstream from either `EastNorth.distance` or raster-pixel distance.
- Generate one immutable anchor sequence per slide and reuse it across every detector and L0/L1/L2 level. All profiles for a slide must therefore have identical profile indexes and physical distances.
- Compute cumulative ground distance by converting consecutive source `EastNorth` anchors through the active JOSM projection and measuring geographic distance. Keep the existing longitudinal anchor count in this patch so the correction does not silently become a sampling-density recalibration. Report the actual physical spacing separately from configured cross-section sampling.
- Keep `anchorScreen` and source-pixel size for raster geometry, interpolation, localization uncertainty, and optimizer normalization. Use cumulative ground distance only for longitudinal metre windows, gap limits, endpoint baselines, physical derivatives, and diagnostics.
- Fail corridor-aware detection explicitly on a non-finite or decreasing physical-distance sequence. Do not fall back to raster pixels or silently relabel projected units as metres.
- A candidate is longitudinally complete only when all unobserved spans are either a tracker-approved internal bridge no longer than 16 profiles and 20 metres, or a supported fixed/movable-anchor approach no longer than the endpoint baseline. A track that terminates while informative corridor bands continue elsewhere is inspection-only.
- Preserve the source-tier rule: complete all-color aggregate and native detector families are evaluated before cross-palette alternatives. Within one source tier, measurable corridor quality is evaluated before detector-specific priors.
- Preserve both raw tracker geometry and final fixed-anchor preview geometry. Raster/tube quality remains tied to raw tracked evidence; topology and connected-way crossing safety use final preview geometry.
- Treat `problems-4.zip` as private, untracked diagnostic input. Do not add the archive, extracted tiles, coordinates, generated CSV files, or `exceptions.txt` to Git.
