# Unattended v0.22 ordinary-action benchmark

Run `python3 scripts/run-v022-benchmark.py --manifest <private-json> --output <new-private-directory>` on one controlled GUI host. The entry point builds the pinned RC6 and candidate plugin JARs, launches a fresh JOSM 19555 process for every warm-up, measured run and cancellation probe, and invokes the registered ordinary Align action. It never calls an AI service. A synthetic harness receipt cannot pass this runner.

The host needs Java 17, JOSM 19555, a working Swing display (`DISPLAY` or `WAYLAND_DISPLAY` with an X-compatible Java display), the complete original OSM layer, both checksum-bound long case archives, and the selected Hot tile fixture. The runner uses an isolated JOSM preferences, data and cache directory for each process. Its transport is offline and a cache miss fails. No real access values or external tile request are needed. A private example manifest with all currently known paths and SHA-256 values is at `build/v022/benchmark-private-manifest.json` in the benchmark worktree; it is ignored by Git. Move or edit the `environment.java` and `environment.josmJar.path` values when using another host, and refresh their hashes. Put all output outside public CI artifacts.

The RC6 adapter is reproducible from `scripts/v022-rc6-benchmark-instrumentation.patch` (SHA-256 `d109ebbca92d6538671a4c11b695562c6d94b0765d2b70dc0d052f048a22839a`). On a separate exact `6288aafe6dc79e948a6981ae795d27ee56a653fe` checkout, verify that hash, run `git apply --check <patch>`, then `git apply <patch>` once; record the resulting five changed paths and their hashes in the private manifest. Do not reset or reapply over the existing instrumented RC6 worktree. The patch adds only benchmark opt-in observation, offline cache-miss failure, a fixed host adapter, and benchmark-only interval plan export; it contains no case, fixture, private path, or credential payload. The runner requires the exact five reviewed path/byte hashes and unstaged/untracked status inventory on RC6 independently of the caller's manifest, rejecting an altered engine or adapter before building.

Manifest schema 1 requires `warmups >= 1`, `repetitions >= 3`, and exactly two cases. `environment` contains an absolute Java 17 executable, `javaMajor: 17`, `josmVersion: 19555`, and a `{path, sha256}` JOSM JAR. `baseline` and `candidate` each contain distinct `worktree` paths, full Git `revision`, and `sourceHashes` mapping every instrumentation or uncommitted path to its SHA-256. The benchmark derives its root from its own script path and holds advisory `flock` locks keyed by that root and each worktree over both JAR builds and all host runs. Each lock filename is SHA-256 of the canonical worktree path plus `.lock` under `josm-v022-benchmark-locks/` in the fixed platform root: `/data/data/com.termux/files/usr/tmp` when it exists, otherwise `/tmp`. An existing but unusable Termux lock root fails closed. This avoids shared-storage filesystems that do not implement `flock` and keeps the lock independent of `TMPDIR`. The parent runner uses the same root key for its JAR build, verification and snapshot, then releases it before invoking the benchmark. Each case contains a safe `id` plus `archive`, `osm`, and `tiles` objects, each `{path, sha256}`. The runner checks the exact RC6 baseline revision `6288aafe6dc79e948a6981ae795d27ee56a653fe`, all declared source hashes, and any dirty worktree path before building. After the candidate is integrated into a new revision, update the candidate revision and source hashes in the private manifest; keep the baseline revision fixed.

When this manifest is supplied to the parent unattended runner's RC profile, `candidate.worktree` must be the exact canonical absolute root of that runner checkout, and `baseline.worktree` must be a canonical external checkout that does not overlap the runner root. This binds the GUI candidate to the same source tree whose JAR the parent runner builds and verifies. Direct standalone use of `scripts/run-v022-benchmark.py` continues to accept an external candidate worktree.

The production observer starts at `AlignWayAction.actionPerformed` and stops after the actual modeless preview dialog becomes visible, after normal source-owner revalidation and diagnostic publication. It then exports the private Format-15 bundle, raw final-geometry digest, selected raster pixel/validity digest, and coordinator cache diagnostics. The historical input archives for these two cases are single `frozen-input.bin` captures; the host rejects a different input kind. Actual interval output carries a benchmark-only frozen edit plan, decoded and compared with every substantive field while each native plan hash is checked against its own archive. The runner rejects missing or wrong-palette/zoom tiles, network transport, changed production input, final geometry, unavailable preview, and a median speedup below 2× on either case. It records each run and comparison log, exit code and timeout in `benchmark.json`. Cancellation probes require a terminal production `CANCELLED` receipt, no preview publication and no slower median terminal response. A complete pass is only possible on a real display host.

On this Termux session Java 17 and the pinned JOSM JAR are present, but `DISPLAY` and `WAYLAND_DISPLAY` are unset and no Xvfb/Xvnc server is installed. The local invocation exits 1 and leaves `benchmark.json` with `UNAVAILABLE`. Supply an already configured display host and run the command above; the runner does not install a display server or change system configuration. It never publishes a release or treats a failed/missing host as a passed RC gate.
