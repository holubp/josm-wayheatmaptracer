# Zero-guarded local certificate: experimental amendment

Status: independent review corrections incorporated; approved for bounded screen
under standing autonomous experiment authority. This is a numerical screen under
the approved Drasov goal, not default adoption or a replacement implementation plan.

## Motivation and unchanged scope

The reviewed full-window policies stop at128Mwork after550/1621/7749of26098R4
pairs. No exact geometry-key reuse was found; ordinary native adjacency already
reaches every state. A shorter profile changes quantile/background/mode semantics
and must not be presented as an exact optimization of the existing certificate.

`ZERO_GUARDED_LOCAL_V1` is an explicit internal evaluator policy only. Preserve all
original native states/ordinary transitions, full configured search width, captured
authority, mandatory events, original ownership, native bilinear scalar integral,
longitudinal probe schedule, objective and128M/8M/256MiB limits. No engine, menu,
Apply/Undo, persisted setting or release/default switch is added by this screen.
The current dense/half/pixel policies remain numerically unchanged.

## Local domain and proof obligations

At each actual connector probe, use local factual native pitch p and
delta=min(requestedStep,minimumNativePitch/2,outputRasterPitch). Center the sample
lattice on that actual connector point, wherever it lies in the full search
corridor. Initial half-window is
`delta*ceil(max(p+6*delta,2.5*p+2*delta)/delta)`; R4 uses4m/17samples.
Never query outside the configured window/decision/acquisition authority. If this
initial window cannot fit, use dense fallback. This does not narrow state search.

Grow the window deterministically by delta as needed. Every sample must use the
existing conservative point authority and strict native-cell support. Local proof
requires observed valid exactly-zero scalar guards on both sides; invalid support
or an artificial window end is UNKNOWN, never a zero or a below-threshold bracket.
This is sampled native evidence, not a raster-wide topology theorem.

For the first implementation, reuse the actual existing accepted-threshold
extractor on these actual local samples, including its quantile computation.
Require its measured profile noise floor to equal0 after zero guards are proved;
otherwise use dense fallback. Do not introduce an unchecked noise-floor override.
Keep each peak's measured local minima/background and existing prominence,
shoulder/core fractions, B3/B5 centers and raw-core/flank receipts.

The new local model admits only resolved modes with sigma<=p/2 and raw-peak to
mode-center displacement<=p/2. An unresolved relevant mode triggers expansion or
dense fallback; never truncate its uncertainty. A selected raw peak is within p
of the connector. Scan potential raw competitors through +/-3p, since selected
center may lie p away, continuation radius is1.5p and raw displacement adds p/2.
Every relevant candidate/competitor needs observed valid +/-2sample B5 taps and
+/-6sample uncertainty taps. Expand for ALL such candidates, not just the winner.
Missing taps, censored support, unresolved ownership or incomplete near competition
cannot authorize a local positive/negative result. Keep all measured alternatives
in the receipt; do not silently remove a competing mode to obtain uniqueness.

Before mutual continuation or a slab check, certify BOTH cross-probe
directions. On the current probe, use the other probe's actual selected center,
radius1.5*min(pCurrent,pOther), and current raw-to-center displacement bound p/2
to enclose every potentially matching raw peak, then require all its +/-2/+/-6
taps. Expand/re-extract either probe or use dense fallback if that entire interval
is not observed/resolved. Recheck both directions after a backend/selection change;
a fixed +/-3p own-probe scan alone cannot certify mutual uniqueness with varying
pitches/offsets. Never filter returned modes merely for lying outside that scan.

Require the existing unique compatible selected mode, observed two-sided shoulder
and raw-core brackets, valid outward continuation and unique mutual continuation.
A fully observed all-zero local domain may return typed LOCAL_NO_MODE. Other
local absences require explicit proof that no raw/censored/suppressed candidate
can be compatible under the bounded model; otherwise expand or use dense fallback.
Remote modes beyond a proved zero guard are outside this explicitly bounded new
model; they cannot supply a local mode through unbounded sigma/center displacement.
This is a semantic change, not evidence that old full-window modes do not exist.

## Fallback, priority and evidence

If local obligations remain unresolved, run the original full-window dense
extractor within the SAME input, owner and attempt budget. Record actual backend
LOCAL or DENSE_FALLBACK, measured window, sample count, expansion/fallback cause
and policy identity. Early refusal additionally records planned probe count,
measured prefix count and first failing slab. Never fabricate a complete local
certificate on fallback.
Work/memory/cancellation stops remain terminal typed unknown; do not catch them
and attempt another backend or reset ledgers. This includes the exact
LocalScalarProfileExtractor.ResourceLimitException wrapper around ledger refusal;
retain that first exception identity on the input across evaluator sessions.

DEFER early-slab optimization in this first screen. Acquire the scheduled probes,
then settle both-neighbor competitor obligations with monotone expansion and at
most one transition to dense fallback per probe. A changed middle probe invalidates
both adjacent proofs; revisit affected neighbors until backend/window/mode/threshold
evidence is stable. Expansion never shrinks a window; dense fallback never returns
to local. Charge every remeasurement and bound this finite process. Freeze the
settled evidence before final mutual/slab decisions. Do not decide a left slab
using provisional middle evidence that a later right neighbor may replace.

Then use the existing exact adjacent-slab loop: reject if its bilinear minimum is
below the larger FINAL accepted endpoint shoulder threshold. This first policy
does not claim an early-prefix speedup. A future early check needs a separate
stability proof and retained regression. Planned/actual probe count, first failing
slab and continuation flags must describe the actual settled or partial evidence.
Existing policy receipt order remains intact.

Charge actual sample reads, each expansion/extraction, fallback, allocation,
integrals and retained diagnostics before work. Bound growing storage; retain
input-wide terminal ownership and cancellation. No free prepass/cache/work pool.

## Acceptance and limits

First implement only the internal policy and deterministic tests. Required controls:
genuine R4 three-arc A/Legacy witness; shifted thin-ridge phases; strong/faint and
broad/uniform images; nearby parallel strands/split; remote bright strand with
and without zero separation; valid/invalid zero guards; one-sided/corner mask;
authority gaps; original/GAP endpoint ownership; zero transport; supported turn
versus dark cross-strand jump; a three-probe case where right-neighbor demand
changes the middle evidence and the left check must use that FINAL middle mode/
threshold; variable-pitch cross-probe competitor in both
directions; cancellation/work/memory terminal behavior, including allocation
refusal INSIDE extraction followed by same-input retry.

Then run the same239state/26098pair R4 graph under unchanged caps. Record work,
actual local/expanded/fallback evidence, outcomes, peak/final memory and leftover
budget for the exact solver. A capped partial graph remains negative feasibility.
Compare common completed old keys truthfully; old unmeasured keys remain unknown.
Independently adjudicate changed admissions from actual mode/slab evidence before
adoption. If no feasible graph/solver margin results, stop this numerical screen;
do not open engine integration on an unsuccessful certificate. Real Drasov/Omice,
strong/sparse/switchback preservation, consumers, topology, replay and release
gates from the original goal remain required.

## Separate exact execution-order experiment

The first capped screen is NEGATIVE (579/26098,128M). Do not adopt this model or
open its inference consumers on that result. A separate execution-only experiment
may stop acquisition at an immutable mode failure; it must not change any local
evidence/threshold predicate, accepted edge, Q, state, source or budget.

Add explicit `ExecutionPolicy.EAGER_ALL_PROBES_V1` and
`STOP_ON_FINAL_MODE_FAILURE_V1`. Existing constructors retain EAGER. A new
four-argument constructor accepts the execution policy; STOP is valid only with
ZERO_GUARDED_LOCAL_V1. Validate selection before opening an owner. Nondefault
execution is identified in receipt parameterVersion and runner identity.

Under STOP, after a probe is acquired, an own-probe failure is final only when its
backend is DENSE_FALLBACK (settling never replaces it), or localNoModeProven is
true. The current eager algorithm rejects on that failure before neighbor settling;
no future probe can make it admit. Return the same failed predicate with actual
measured prefix, planned count, incomplete continuation/envelope and charged work.
Do not stop early on positive LOCAL evidence, provisional mutual/slab decisions,
unknown local proof, or terminal resource errors disguised as ordinary negatives.
Keep existing post-acquisition/settling behavior for all other outcomes.

This changes execution/diagnostic suffix availability, not the numerical model.
An interrupted/unmeasured suffix is never exported as measured. Cancellation and
memory/work errors remain terminal across sessions. Preserve full source scalar
integral, admitted Q, state order and zero-arc ownership. Broader skipping of local
expansion is NOT authorized by this proof; its fixpoint remains unproved.
